## Q2. New defects

### 1. The serializer can defeat the deadline unless two locks are explicitly separated

This is a blocker and the same runtime-isolation root again.

Suppose serialization holds one lock while calling `NSSpellChecker`. If the checker stalls, the timeout handler tries to acquire that same lock to set `.unavailable(.oracleTimedOut)`. `withOrderedDeadline` waits for `onTimeout` to finish before resuming paste at [TaskTimeout.swift:127-133](/Users/m4pro_sv/Developer/EnviousLabs/EnviousWispr-1803-dict/Sources/EnviousWisprCore/TaskTimeout.swift:127). Paste would therefore hang behind the stalled checker despite having a deadline.

The runtime needs two synchronization domains:

- A short-lived state lock, never held during any system call.
- A separate serial checker queue/gate, whose wait and system call are both inside the deadline.

Timeout cleanup may touch only the state lock. Once disabled, later calls must refuse before entering the checker queue. An already queued call must recheck the runtime generation after acquiring the queue.

The required transitions are:

- Initial → warming.
- Warming + preparation success → ready.
- Warming + preparation failure → unavailable.
- Warming + decision → refuse warming, state unchanged.
- Ready + successful decision → ready.
- Ready + dictionary disappears → unavailable.
- Ready + timeout wins → unavailable before paste resumes.
- Timeout winner + late result → result discarded; state stays unavailable.
- Unavailable + any later decision/prewarm → refuse; no checker access.

Those transitions are complete once the two-lock rule and late-result rule are binding.

## Q4. Drop-in edits

### A. Make serialization compatible with timeout

Add this immediately below the four-concern ownership table:

> **Two synchronization domains are mandatory.** Runtime state and spell-checker execution must never share a lock. A short-held state lock owns only the current state and generation; it is never held while calling AppKit or NaturalLanguage. A separate serial checker queue owns every touch of `NSSpellChecker`. Queue acquisition, identifier revalidation and the system call all occur inside the caller’s ordered deadline.
>
> `onTimeout` touches only the state lock: it advances the generation and permanently sets `.unavailable(.oracleTimedOut)` before paste resumes. It never waits for the checker queue. An operation rechecks the generation after acquiring the checker queue and before its first system call. If timeout already won, it exits without touching the checker. If timeout wins during a system call, that late result is discarded and cannot change runtime state. Every later decision refuses before entering the checker queue.
>
> Binding transitions:
>
> | From | Event | To / result |
> |---|---|---|
> | initial | runtime constructed | `.warming(generation: 0)` |
> | `.warming` | preparation succeeds | `.ready(oracle, same generation)` |
> | `.warming` | preparation fails | `.unavailable(reason)` |
> | `.warming` | paste arrives | refuse `.oracleWarming`; state unchanged |
> | `.ready` | decision succeeds | return decision; state unchanged |
> | `.ready` | English identifier no longer available | `.unavailable(.dictionaryUnavailable)` |
> | `.ready` | ordered deadline wins | increment generation; `.unavailable(.oracleTimedOut)` before paste resumes |
> | any prior generation | late completion | discard result; never mutate current state |
> | `.unavailable` | any decision or repeated prewarm | refuse stored reason; no checker access |

```swift
  var generation = 0
  var phase: Phase = .warming

private static let stateLock =

private static let checkerQueue =
  DispatchQueue(label: "co.enviouslabs.wispr.english-word-oracle")

package static func disableAfterTimeout() {
  stateLock.withLock { state in
    state.generation += 1
    state.phase = .unavailable(.oracleTimedOut)
  }
}
```

```swift
guard case .ready = stateLock.withLock({ $0.phase }) else {
```

```swift
let stillCurrent = stateLock.withLock { state in

guard stillCurrent, !Task.isCancelled else {

}
```
