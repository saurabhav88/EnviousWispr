## Q2. New defects

### 1. Warm-up is an optimization, not heart-path isolation

This is the blocking defect.

The plan never says who calls the warm-up. It does not define what production does while warm-up is running or if it never finishes. A first paste can beat a fire-and-forget task and pay the full cold cost.

Even after warm-up, later calls into `NSSpellChecker` or `NLTagger` remain synchronous and unbounded. Therefore a deadline is still required for the heart guarantee. The warm-up prevents normal cold latency; the deadline protects against abnormal service stalls. They solve different problems.

The correct home is `WisprBootstrapper`, beside its existing launch prewarm at [WisprBootstrapper.swift:1017](/Users/m4pro_sv/Developer/EnviousLabs/EnviousWispr-1803-dict/Sources/EnviousWisprAppKit/App/WisprBootstrapper.swift:1017). Readiness ownership belongs inside `EnglishWordOracle`, not `AppLifecycleCoordinator`.

If paste beats warm-up, casing must refuse with `.oracleWarming` while spacing and seam repair continue. If a live decision times out, disable the oracle for the remainder of the process before resuming paste. That prevents a second call racing an abandoned call against the one shared spell checker.

### 2. Canary removal is sound, but the plan still describes a nonexistent guarantee

Selecting an identifier from `availableLanguages` makes the measured `"xx"` misuse unreachable. No canary replacement is needed.

However, the cached identifier should be revalidated as still present before each spell lookup. Otherwise a dictionary removed or changed during a long-running process recreates the stale-identifier path. This check belongs inside the same deadline.

Delete the remaining canary claims; do not invent a new health check.

### 3. The human ship gate is not executable and its denominator is biased

At plan line 493:

- There is no sample size.
- There is no exact seed operation.
- Rows have no stable IDs.
- The generator’s input order is not sorted.
- The reviewer sheet and hidden answer key are unspecified.
- Mixing every generated-capital disagreement into the precision denominator oversamples likely negatives. That is a safety audit, not an unbiased precision estimate.

Use a deterministic 500-row sample from all oracle-lowered candidates for the precision denominator. Add every generated-capital row as a separate mandatory safety review, reported separately. Include randomized keep-decision decoys so the reviewer is actually blind to the oracle decision.

### 4. The 15-word set is bounded, but not justified as written

It is meaningfully different from the 799-word vocabulary list because it is frozen and targets one measured tagger failure shape. But it is not “the closed grammatical class” of English indefinite pronouns or deictic time words. Those classes contain other words not listed.

More importantly, the plan ablated the deleted sibling but never reports `no exceptions` versus `15 exceptions` on the 11,562 rows. It therefore does not yet show what these 15 entries buy. Run that ablation. Keep only entries with either an existing shipped contract, such as `yesterday`, or measured continuation benefit.

### 5. Remaining internal contradictions can produce the wrong implementation

The stale canary, telemetry counts, resource line counts, P2 wording, P8 overclaim, duplicate damage paragraph at lines 185 and 187, and false artifact docstring are not cosmetic. They describe conflicting implementation and test obligations.

```swift
import Foundation
import os

package enum EnglishWordOracleRuntime {
  private enum State: Sendable {
    case warming
    case ready(EnglishWordOracle)
    case unavailable(CursorInsertionRepair.CaseSkipReason)
  }

  private struct Storage: Sendable {
    var prewarmStarted = false
    var state: State = .warming
  }

  private static let storage = OSAllocatedUnfairLock(initialState: Storage())

  package static func prewarm() {
    let shouldStart = storage.withLock { storage in
      guard !storage.prewarmStarted else { return false }
      storage.prewarmStarted = true
      return true
    }
    guard shouldStart else { return }

    DispatchQueue.global(qos: .utility).async {
      let prepared = EnglishWordOracle.prepare()

      storage.withLock { storage in
        guard case .warming = storage.state else { return }
        switch prepared {
        case .success(let oracle):
          storage.state = .ready(oracle)
        case .failure(let reason):
          storage.state = .unavailable(reason)
        }
      }
    }
  }

  package static func snapshot() -> EnglishWordOracle {
    storage.withLock { storage in
      switch storage.state {
      case .warming:
        return .unavailable(reason: .oracleWarming)
      case .ready(let oracle):
        return oracle
      case .unavailable(let reason):
        return .unavailable(reason: reason)
      }
    }
  }

  package static func disableAfterTimeout() {
    storage.withLock { storage in
      storage.state = .unavailable(.oracleTimedOut)
    }
  }
}
```
